Lab 0 · 5 min

The Data Foundation Tour

Why: You need to understand what's already connected before adding new data sources.

Before we build, let's see what's already here. Your org has data flowing in from CRM, Marketing Cloud, web, commerce, and ad platforms — all unified into customer profiles. Let's take a quick tour.

1

Navigate to Data Cloud Setup

From the top navigation bar, click the gear icon (⚙️) and select Data Cloud Setup directly from the dropdown menu. This takes you into the Data Cloud configuration home page. Then scroll down on the left-hand menu and click Other Connectors.

Connectors are how Data Cloud ingests data from external systems. Each connector represents a live pipe — Snowflake, S3, Marketing Cloud, etc. — and the Other Connectors page shows you what's already wired up before you add your own.

You'll see the Data Cloud connectors page with two existing connections already configured (AWS Demo Connector and UploadedFiles).

2

Explore the Data Model

Using the App Launcher (grid icon, top-left), search for and open "Data Cloud". Then click the Data Model tab to see all the data model objects (DMOs).

DMOs are the normalized schema layer in Data Cloud. Raw data from every source gets mapped into DMOs — standard (Individual, Contact Point) or custom (External Orders). This abstraction is what lets you query across CRM, web, and ad data with one unified model instead of source-specific schemas.

Notice the existing DMOs: web engagement, commerce transactions, Google/Meta ad performance, email and SMS engagement — all mapped to standard or custom data model objects.

3

Check the Data Streams

Click the Data Streams tab. You'll see all the active data streams that are feeding your Data Cloud instance.

A data stream is the live ingestion pipeline between a source system and its target DMO. Each stream has its own schedule, field mapping, and error tracking. Streams can be real-time (streaming) or batch (scheduled refresh), and they track record counts so you can verify data is flowing correctly.

💡
Why this matters: Without Data 360, a marketer sees a Contact in CRM, maybe an email open in Marketing Cloud, maybe a purchase in Commerce — three disconnected views. With Data 360, all these signals flow into one unified profile. That's the foundation we'll build on.

Connect Snowflake & Ingest Orders Data

Why: Your most valuable data often lives outside Salesforce — connecting it without moving it is the foundation of a unified view.

Now for the big unlock: pulling data directly from Snowflake into Data 360 using Zero Copy. This means the data stays in Snowflake — no duplication, no data movement — and Data Cloud can query it directly.

1

Navigate to Other Connectors

Go to Setup → In the left sidebar under Data Cloud, find and click Other Connectors.

Data Cloud separates connectors into two categories: CRM connectors (built-in Salesforce object sync) and "Other" connectors for third-party systems like Snowflake, S3, and Google Cloud Storage. We're using Other Connectors because Snowflake is an external data warehouse, not a native Salesforce object.

⚠️
Important: Do NOT go to the "Integrations" or "Connections" tab in the main nav bar — that's for Automation connectors, not Data Cloud connectors. You need the one under Setup → Data Cloud → Other Connectors.
2

Create a New Snowflake Connector

Click the New button in the top-right corner. A dialog will appear asking you to select a connector type.

Data Cloud supports dozens of connector types out of the box — cloud warehouses (Snowflake, BigQuery, Redshift), file stores (S3, GCS, Azure Blob), and SaaS platforms. Each has its own authentication model and ingestion strategy (Zero Copy, batch, streaming).

3

Search for and Select Snowflake

In the search box, type "Snowflake". Select the Snowflake connector (Zero Copy) and click Next.

Zero Copy means Data Cloud creates a federated link to your Snowflake warehouse — it pushes queries down to Snowflake at execution time rather than copying rows into Salesforce storage. This eliminates ETL latency, avoids data duplication costs, and means Snowflake stays the system of record.

Lab 2 · 10 min

Build a Unified Customer Profile

Why: Data from different sources has different IDs — identity resolution stitches them into one customer profile so you stop treating the same person as three strangers.

Now that Snowflake orders data is flowing in, we need to add it to identity resolution so Data Cloud can stitch order records to existing unified profiles. This is the "aha" moment — where fragmented data becomes a single customer truth.

1

Navigate to Identity Resolution

In the Data Cloud app, click More in the top nav, then Identity Resolution. Switch to the "All Identity Resolutions" list view to see all rulesets. You'll see two: Gray Rock Account Match (for company-level matching) and Gray Rock Individual Match (for person-level matching).

Identity resolution rulesets define how Data Cloud matches records from different sources to the same real-world entity. Account-level matching stitches company records; Individual-level matching stitches person records. Each ruleset specifies match keys (email, phone, name), match rules (exact, fuzzy, normalized), and reconciliation logic for which source wins on conflicts.

The "All Identity Resolutions" view shows both rulesets — Gray Rock Account Match and Gray Rock Individual Match. Profile counts will vary based on the data in your org.

2

Open the Individual Ruleset

Click on the Gray Rock Individual Match identity resolution ruleset to open it. This is where Data Cloud matches records from different sources to the same person.

The Individual Match ruleset uses Profile-category DMOs (Individual, Contact Point Email, Contact Point Phone) as inputs. Match rules specify comparison logic — "Email Exact Normalized" lowercases and trims whitespace before comparing, catching mismatches like "John@gmail.com" vs "john@gmail.com". Reconciliation rules determine which source's field value wins when two matched records disagree (e.g., CRM name vs web form name).

The Individual Match detail page shows the match rules, source data, and consolidation metrics. Notice how records from multiple sources are stitched together using email as the primary match key.

3

Add Your New Data Source

Review the match rules configuration in the Individual Match ruleset. Notice how existing sources like Contact, Lead, and Contact Point Email are connected through match rules.

Identity resolution only accepts Profile-category DMOs (Individual, Contact Point Email/Phone/Address) — not "Other"-category objects like External_Orders. To include order data in a unified profile, you'd link it through a relationship to an Individual or Contact Point object (e.g., CUSTOMER_EMAIL → Contact Point Email). This is a deliberate Data Cloud design choice: profile-level matching keeps identity graphs clean and prevents transactional data from creating false merges.

⚠️
Note: The External_Orders DMO is categorized as "Other" — identity resolution only works with Profile-category objects (Individual, Contact Point Email, Contact Point Phone, etc.). To include order data in identity resolution, you would need to create a relationship between the orders data and an Individual profile through a Contact Point object (e.g., matching on CUSTOMER_EMAIL). For this workshop, we observe the existing IR configuration.
4

Run Identity Resolution

Review how identity resolution processes records by examining the match rules (Email Exact Normalized, Phone Exact) and reconciliation rules. In a production environment, you would run identity resolution after adding new data sources to stitch new records into unified profiles.

When IR runs, it executes a multi-pass algorithm: first it indexes all records by each match key, then it finds candidate pairs that share a key, applies the match rules to score each pair, and finally merges qualifying pairs into unified profiles. The output is a "Unified Individual" — a synthetic record that consolidates the best field values from all matched source records according to the reconciliation rules.

5

Explore a Unified Profile

Navigate to the Profile Explorer tab (under More in the top nav). If identity resolution has been run and unified profiles exist, you can search for and explore a unified individual profile to see all the data sources that contribute to it — CRM records, email engagement, web behavior, and ad interactions combined into one view.

Profile Explorer queries the Unified Individual DMO and joins all related DMOs through their relationships. What you see is the output of identity resolution + data model relationships working together — a single profile page that aggregates a person's CRM record, email engagement history, web events, purchase transactions, and ad impressions, all linked through the identity graph.

⚠️
Note: If Profile Explorer shows no results, identity resolution may not have been run yet on this org, or there may be 0 unified profiles. Your facilitator will demonstrate a pre-populated Profile Explorer view.
🎯
The unified profile tells the complete story. One customer, one truth — their purchase history from Snowflake, email engagement from Marketing Cloud, web browsing behavior, CRM contact data, and ad interactions. This is the foundation that makes everything else possible.

Lab 3 · 12 min

Agentic Segmentation — Audience in Plain Language

Why: Marketers need audiences fast — not SQL queries and IT tickets. AI segmentation lets you describe who you want and get it instantly.

This is the hero moment. Instead of writing SQL or submitting an IT ticket, you'll describe the audience you want in plain English — and Data 360's AI will build the segment from your unified, governed data.

1

Navigate to Segments

In the Data Cloud app, click the Segments tab. Switch to the "All Segments" list view (not "Recently Viewed"). You'll see four existing segments already created for this org.

Segments in Data Cloud are reusable audience definitions that query against unified profiles in real time. Unlike static lists, segments are dynamic — their membership recalculates on every publish cycle, so new profiles that match the criteria are automatically included and lapsed ones are removed.

Four pre-built segments are already active: GR Account-Linked Individuals, GR All Unified Individuals, GR Email Contactable, and GR Phone Contactable. Each uses Standard type on the Unified Individual gr01 entity. Population counts will vary (may show 0 if identity resolution hasn't been run).

2

Inspect an Existing Segment

Before creating your own, click on one of the existing segments (e.g., GR Email Contactable) to see how it's built — the filters, member count, and data sources used.

Each segment's detail page shows the filter criteria, the target entity (Unified Individual), the population count, and the activation status. Filters can reference attributes from any related DMO — not just the base entity. This is how a single segment can combine CRM data, email engagement, web behavior, and purchase history in one audience definition.

The segment detail page shows the criteria, member preview, and activation status. Notice how the segment draws from unified profiles across multiple data sources.

3

Create a New Segment

Go back to the Segments list and click New Segment. Choose Standard segment type and Standard Publish. Select Unified Individual gr01 as the target entity (not just "Individual"). Name your segment (e.g., "GR Win-Back Campaign"). You'll be presented with the segment builder.

You must select "Unified Individual gr01" — the output of identity resolution — not the raw "Individual" DMO. The unified entity contains deduplicated, reconciled profiles. Segmenting on raw Individual would include duplicates and miss cross-source matching. "Standard" type means all qualifying profiles are included; "Waterfall" is for exclusion-based sequential segmentation.

4

Use AI to Build Your Audience

In the segment builder, look for the AI prompt input — a text field with a sparkle/AI icon where you can describe your audience in plain English. This is Data 360's Agentic Segmentation powered by Agentforce.

✨ Type This Prompt

"Find customers who spent over $200 in the last quarter but haven't opened an email in 30 days"

Press Enter or click the submit button. The AI will translate your natural-language request into segment filter criteria automatically — no dragging, no manual filter building. This is the power of combining unified data with AI.

Agentic Segmentation uses a large language model (via Agentforce) that understands your org's data model — the DMOs, their fields, relationships, and data types. It parses your natural-language prompt, maps concepts like "spent over $200" to the correct DMO attribute and operator, and generates the filter tree. The result is identical to what you'd build manually — it's just dramatically faster and accessible to non-technical users.

💡
Tip: You can also explore the Attributes panel on the left to see the fields available from the Unified Individual entity and related Data Model Objects. These are the same attributes the AI uses behind the scenes to build your segment criteria.
5

Review & Refine

Data 360 will translate your prompt into segment criteria. Review the filters it created — notice how each filter maps to a different underlying data stream. You can refine any filter manually if needed.

The AI-generated filters are fully editable — they're standard segment criteria, not a black box. You can adjust operators, change thresholds, add/remove conditions, or combine AI-generated filters with manual ones. This "AI-assisted, human-governed" approach means you get speed without sacrificing control or auditability.

6

Preview & Activate

Check the segment count and the member preview. These are real, resolved unified profiles — not duplicate records. Click Save to save your segment, then click Done to exit the builder. Your segment is now saved and can be activated in Lab 4.

The count reflects deduplicated unified profiles, not raw source records. If one person exists as a Contact in CRM, a subscriber in MCE, and an order record in Snowflake, they count as one profile — not three. This is the direct payoff of identity resolution: accurate audience sizing that prevents wasted ad spend and duplicate outreach.

1

Open Activation Targets

In the Data Cloud app, click More → Activation Targets. Switch to the "All Activation Targets" list view. You'll see three pre-configured targets: GR_Marketing_Cloud_Target (Salesforce Marketing Cloud), GR_S3_Data_Export (S3), and GR_CRM_Sync_Target (Salesforce CRM). All are initially Inactive.

Activation targets are the outbound pipes from Data Cloud to downstream systems. Each target type has its own connector, schema mapping, and delivery mechanism. MCE targets push audiences into Marketing Cloud data extensions for journey entry; S3 targets export flat files for ad platforms; CRM targets write enriched data back to Salesforce objects for sales reps.

Three activation targets are ready to go — each pushes your segment to a different channel for coordinated multi-channel activation.

2

Activate to Marketing Cloud

Select GR_Marketing_Cloud_Target. Review the target configuration — Platform: Salesforce Marketing Cloud, Data Space: default. To activate, you would click Enable, then create a new activation using your newly created segment to push the audience to MCE for an email journey.

When a segment is activated to MCE, Data Cloud publishes the segment membership as a data extension in Marketing Cloud. Journey Builder can then use that data extension as an entry source — every time the segment refreshes, new qualifying profiles automatically enter the journey. This eliminates manual list imports and ensures the journey always targets the freshest, most accurate audience.

The handoff: Data Cloud segment → MCE audience → Journey entry. Your segment members flow automatically into Marketing Cloud, ready for a personalized email or SMS journey.
3

Activate to S3 for Paid Media

Select GR_S3_Data_Export. The segment exports unified, deduplicated audiences for paid media platforms — Google Ads, Facebook, TikTok — for suppression, retargeting, and lookalike modeling.

S3 activation exports the segment as a file (CSV/JSON) to an S3 bucket, which ad platforms can ingest via their audience upload APIs. The key advantage: the exported audience is deduplicated by identity resolution, so you're not paying for duplicate impressions on the same person across Google and Meta. You can also use the export for suppression lists — excluding existing customers from acquisition campaigns to reduce wasted spend.

⚠️
Note: This target uses the S3 (Legacy) connector type. Salesforce is retiring the legacy S3 activation target — use the new Amazon S3 activation target for production configurations.
4

Activate to Salesforce CRM

Select GR_CRM_Sync_Target. Enriched profiles flow back to Sales Cloud so reps see the same customer intelligence the marketing team used to build the audience.

CRM activation writes Data Cloud attributes back to standard Salesforce objects (Contact, Lead, Account). This means sales reps see segment membership, engagement scores, and cross-channel behavior directly on the Contact record — no switching between systems. It's also the foundation for triggering Flows: e.g., when a high-value contact enters a "Win-Back" segment, a Flow auto-creates a task for the account owner.

🚀
One audience, three channels, under a minute. Your email team, your paid media team, and your sales team are all working from the same customer truth. That's what a CDP is supposed to do. And the activation is real-time or scheduled — not a batch export that's stale by the time it arrives.

Measure & Optimize — Insights That Close the Loop

Why: Without measurement, you're guessing — calculated insights turn campaign results into data that improves your next move.

The final piece: closing the loop. Data 360 doesn't just push data out — it brings signal back in, making every subsequent campaign smarter.

1

Explore Calculated Insights

In the Data Cloud app, click More → Calculated Insights. Switch to the "All Calculated Insights" list view. Your org has three pre-built GR calculated insights (plus a system CI):

Calculated Insights are SQL-based aggregation objects that run on a schedule and materialize results as new DMO records. Think of them as pre-computed metrics — instead of calculating "total email opens in 30 days" at query time across millions of events, the CI runs once, stores the result per profile, and makes it instantly available for segmentation, activation, and reporting. This is how Data Cloud converts raw event data into actionable intelligence at scale.

GR Google Ads Campaign Summary — Ad campaign performance insights
GR Meta Ads Campaign Summary — Ad campaign performance insights
GR Email Engagement Metrics — Email engagement tracking
2

See the Closed Loop

Follow along with your facilitator to see how engagement signals flow back into Data Cloud:

This is the closed-loop architecture: Data Cloud sends audiences out (activation), the destination system generates engagement events (opens, clicks, conversions), those events flow back into Data Cloud via data streams, calculated insights aggregate them into profile-level metrics, and those metrics feed the next round of segmentation. Each cycle makes your audiences smarter — your "high-value customers" segment automatically reflects the latest purchase and engagement data.
